古董局中局 v10.8.14 完整版安裝說明

一、安裝
1. 解壓縮 gudong_v10_8_14_full.zip。
2. 將解壓後 gudong_v10_8_14 專案資料夾內的全部內容部署至原本靜態網站／GitHub Pages 專案位置。正式版本識別以 VERSION.txt、首頁及 js/config.js 為準。
3. 不要只替換單一 JS 檔案。本版更新多個互相依賴的 mind、strategy、speech、claims、engine、learning、tactics 模組及測試文件。
4. 部署後確認首頁標籤與 js/config.js 均顯示 10.8.14。
5. 若使用 GitHub Pages，提交完整專案後等待部署完成，再以無痕視窗／強制重新整理確認快取已更新。

二、本機回歸測試
在專案根目錄執行：
  node tests/run-v10-8-14-regressions.js

此腳本依序執行 42 個指定回歸／冒煙測試，對已知有隨機性的方震策略測試允許一次重試；測試結果會寫入 TEST-RUN_v10.8.14.log。

語法檢查可執行：
  node --check js/**/*.js
  node --check tests/*.js

若 shell 不支援遞迴 glob，請用 find 列出 js/ 與 tests/ 下所有 .js 檔後逐一執行 node --check。

三、建議真人驗收
1. 鄭國渠前兩輪：確認共同錯誤真品主張及共同投向已公開贗品才會形成隊友盲認，不能只因同一句話就定隊友。
2. 老朝奉／藥不然：確認 `pZheng` 與 `pEvil`、`pLao` 分離；藥不然不應優先偷襲高可信鄭國渠。
3. 角色偽裝：確認公開假身分跨輪延續；沒有明確解釋時，不應任意從黃煙煙改成姬雲浮。
4. 投票：確認重複喊真只是軟票向；「我應該會投」不會被當成硬承諾，仍可合法分票與棄票。
5. 時序：傳牌尾家仍決定公開發言起點；`passOrder` 與 `speechOrder` 維持分開。
6. 發言：確認刪除模板與重複語句後仍保留證據、獸首與立場，不洩漏私有思考。

四、限制
勝利機率、角色後驗及偷襲風險均屬啟發式推理值，並非大樣本實戰校準機率。本版未完成配對 A/B 勝率驗證；本機 Mock Firestore 測試也不等於正式 Firebase 多裝置驗收。正式部署後仍需真人多裝置測試。

完整修改請看 CHANGELOG_v10.8.14.md；測試結果請看 TEST-REPORT_v10.8.14.txt；待驗證項目請看 BACKLOG_20_v10.8.14.md。
